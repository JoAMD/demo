**Fix findStep to include trigger (per D-16):**

The current `findStep` only searches `flow.steps`. Modify it to also check `flow.trigger`:

In `StepInspector`, the `step` useMemo calls `findStep(flow.steps, selectedStep)`. Change this to:
```typescript
return findStep([flow.trigger, ...flow.steps], selectedStep);
```
This prepends the trigger to the search array so findStep finds it. Do NOT modify the findStep function itself — the simpler fix is at the call site.

**Add empty payload message (per D-09):**

In the `StepContent` component, when `step.kind === 'trigger'` and the payload is an empty object (`Object.keys(payload).length === 0`), show "No payload provided" instead of the normal event display.

To access payload in StepContent, add a `payload` prop (passed from StepDetail, which gets it from the store). Or read it directly from the store inside StepContent using `useTraceStore(useShallow(s => s.payload))`.

The trigger case currently shows `{step.event}`. Add a check: if payload is empty, render:
```tsx
<div className="text-[14px] text-[#a1a1aa]">
  <span className="text-white">Event:</span> {step.event}
  <div className="mt-2 text-[12px] text-[#52525b] italic">No payload provided</div>
</div>
```

This only shows AFTER a trace run (when results exist), not before. The existing EmptyState handles the pre-run case.

  - Row layout: `name` (font-mono), `predicate` (from the filter — need to pass step.filters to resolve), `value` (the filter's comparison value), then the ACTUAL resolved value from conditionResults, then a PASS/FAIL pill
