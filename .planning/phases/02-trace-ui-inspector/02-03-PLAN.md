**Dropdown:**
- `<select>` element, controlled by `selectedContact?.email ?? ''`
- Placeholder option: `<option value="">Select a test contact...</option>` (UI-SPEC copy)
- Each contact: `<option key={contact.email} value={contact.email}>`
  - Display: `{contact.first_name} {contact.last_name} ({contact.email})`
- Styling: match existing flow selector in JsonEditor — `bg-card text-white border border-border rounded-lg px-3 py-2 text-sm outline-none focus-visible:ring-2 focus-visible:ring-accent`

**Auto-merge on select (D-11):**
- `onChange` handler:
  1. Find contact by email from fixtures
  2. If found: merge `contact.*` fields into current payload
     ```
     const newPayload = { ...payload };
     Object.entries(contact).forEach(([key, value]) => {
       newPayload[`contact.${key}`] = value;
     });
     setPayload(newPayload);
     setSelectedContact(contact);
     ```
  3. If placeholder selected (empty value): setSelectedContact(null), don't modify payload

**Why `contact.*` prefix:** The execution engine uses `getNestedValue(payload, filter.name)` where filter.name is like `contact.engagement_rating`. The payload needs top-level keys like `contact.engagement_rating`, not nested `contact: { engagement_rating }`. This matches how Nitrosend payloads work — contact fields are flat with dot prefix.

**Label:** `<label className="text-xs text-secondary">Contact</label>` above the dropdown (UI-SPEC label style).
