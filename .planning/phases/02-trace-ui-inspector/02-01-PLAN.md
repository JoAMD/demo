Create `src/components/StepInspector.tsx` — default export React component.

**Per D-02:** Shows ONE step at a time (detail card, not list). Reads `results` and `selectedStep` from traceStore via `useShallow`.

**Component structure:**
- Import `useTraceStore` and `useShallow` from zustand
- Import `useMemo`, `useCallback` from react
- Import types: `StepResult` from engine/types

**Store selectors (useShallow):**
- `results` — array of StepResult
- `selectedStep` — string | null (step ID)
- `setSelectedStep` — setter
- `flow` — Flow | null (to look up step details like subject, body, filters)

**Step lookup:** Find the Step object from `flow.steps` (recursively for split children) matching `selectedStep` ID. Also find the StepResult matching `selectedStep`.

**Empty state (D-05):** When `results.length === 0` or `selectedStep === null`:
- Full-height div, centered text
- Heading (20px/600): "Run a trace to see results"
- Body (14px/400): "Enter an event payload and click Run Trace to see how your flow evaluates."
- Use text-secondary for body color

**Step detail card:** When step found:
- Step name (16px/600, text-primary) at top
- Kind badge: small rounded pill with step kind text (12px/400)
- PASS/FAIL pill (D-02, INSP-02): 
  - `passed === true` → green tint bg (`bg-success/10`), text-success, label "PASS"
  - `passed === false` → red tint bg (`bg-error/10`), text-error, label "FAIL"
  - 12px/400 text, rounded-full, px-2 py-0.5

**Email step rendering (D-03, D-07, INSP-04):**
- Look up the Step object (kind === 'email') from flow
- Default: rendered preview — show subject as heading (16px/600), body as HTML (dangerouslySetInnerHTML in a scrollable container with `overflow-y-auto`)
- Toggle button: "Rendered" / "Raw HTML" — switches between HTML render and plain textarea showing raw HTML source
- Toggle styled as two-segment button with accent color on active segment
- Container: `flex-1 overflow-y-auto` so long emails scroll within full panel height

**Split step rendering (D-08, INSP-03):**
- Look up the Step object (kind === 'split') from flow
- Show branch taken: "Branch: yes" or "Branch: no" as a pill (accent color bg)
- Show all conditions in a list:
  - Each condition row: expression text (e.g., `engagement_rating eq high`) | resolved value (from payload) | PASS/FAIL pill
  - Expression: 14px/400, monospace font
  - Resolved value: 14px/400, text-secondary
  - Per-condition PASS/FAIL: small pill matching the overall step pass/fail

**Other step types (webhook, sms, trigger):**
- Show step kind and basic info (URL for webhook, message for sms, event for trigger)
- Smaller content area but panel stays full height (D-03)

**Wait step handling:** If a wait step exists in the future, show duration info in the row. For now, display the step kind with a note "Wait step — duration display coming soon".

**Prev/Next navigation (D-04):**
- Bottom of panel: two buttons "← Previous" / "Next →"
- Disabled when at first/last step
- `onKeyDown` handler on the panel div: ArrowLeft → prev, ArrowRight → next
- Only active when `selectedStep !== null`

**Liquid tooltip (simplified from roadmap 2.7):**
- On split condition resolved values, show a small tooltip on hover: "Source: {filter.name}" 
- Use native `title` attribute for simplicity (ponytail: stdlib tooltip over custom component)

**Styling:**
- Full height: `h-full flex flex-col`
- Panel padding: p-4 (UI-SPEC md=16px)
- Background: bg-sidebar (`#1a1a1a`)
- Border: border-r border-border
- Active step indicator: 3px left border accent color on the detail card

**Performance:** Use `useShallow` on all store selectors. Memoize step lookup with `useMemo`.
